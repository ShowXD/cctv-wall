# 使用說明

## 主畫面

| 操作 | 結果 |
| --- | --- |
| 左側地點列表 | 樹狀清單。點地點切換地點（**只有選中的地點會建立連線**）；展開後點單台攝影機會切到該地點並把它放大 |
| 左側清單拖曳 | 拖地點改地點順序、拖攝影機改同地點內的順序，放開即存檔。不能把攝影機拖到別的地點，那要在設定視窗做 |
| 左側地點按右鍵 | 立即觀看、新增攝影機、複製地點、重新命名或刪除地點；攝影機子項則是觀看該地點或開啟設定視窗編輯 |
| 左下 `管理設定` | 開啟設定視窗，編輯地點與攝影機 |
| 雙擊任一格影像 | 該路**原地放大**填滿整個程式畫面（不開新視窗）；再次雙擊或按 `Esc` 回到原本頁面 |
| 影像上按右鍵 | 快速切換該攝影機的 Stream 1～4（無法辨識串流編號的直接 URL 除外） |
| `F11` | 全螢幕；`Esc` 離開 |

控制列（由左至右）：

| 按鈕 | 作用 |
| --- | --- |
| `‹` / `›` | 同一地點內翻頁（每頁格數由效能檔決定），中間顯示「第 X / Y 頁」 |
| 效能模式下拉 | 切換效能檔，**立即生效**，不需重開程式 |
| 語言下拉 | 繁體中文 ／ English，**立即套用**並記住 |
| `🔇` | 全部靜音。只在 `full` 效能檔出現，且只有正在聆聽某一台時可按 |
| 格子按右鍵 → `聆聽這台攝影機` | 一次只有一台出聲，其餘保持靜音；出聲的格子邊框轉綠並顯示 `🔊 名稱` |
| `□` | 以影像填滿程式畫面（收起導覽與工具列，保留視窗標題列）；再按或 `Esc` 還原 |
| `↻` | 重新連線目前可見的攝影機 |
| `☷` | 事件紀錄：直接在程式內看 `cctv-wall.log` 的尾端，可重新整理 |

畫面上方顯示目前地點、攝影機數量，以及右上角的 `● 4/4 路播放中` 播放徽章。
底部狀態列顯示操作提示，右側顯示本程式的播放器數、CPU 用量與工作集記憶體，每兩秒更新。
CPU 寫成 `3.8/16 核 (24%)`：本程式相當於用掉 3.8 顆核心，佔整台機器 24%。

為降低低階電腦與 NVR 同時建立多條 RTSP 連線的壓力，當前頁的攝影機會依效能檔錯開建立，
切換地點或頁面時則立即取消尚未建立的連線並釋放所有舊播放器。

畫面自動排成接近正方形的格子：4 路 → 2×2，5～6 路 → 2×3，9 路 → 3×3，16 路 → 4×4。

單格狀態刻意分成兩級，避免正常的緩衝把畫面塞滿文字：

| 情況 | 呈現 |
| --- | --- |
| 播放中 | 沒有任何覆蓋物，滑過去的提示顯示「播放中」 |
| 連線中／未收到影像 | 只更新該格的滑過提示，不遮擋畫面 |
| 連線失敗 | 該格顯示紅色訊息與原因，其他畫面照常播放 |

## 斷線自動重連

攝影機掉線後那一格會自己重連，不需要人工介入。

- 判斷來源是 `WallView.audit_now()` 每 5 秒一次的健康稽核。播放狀態落在
  `ERROR` / `ENDED` / `IDLE`，或一開始就連不上時，就排入重連。
- **正在連線中（`OPENING`）不算掉線**：低階電腦協商本來就慢，把它當故障
  會不斷打斷一個其實正在連線成功的來源。
- 退避間隔 5 → 10 → 20 → 30 秒（上限 30 秒），避免壞掉的來源被反覆猛打。
  影像一旦恢復，間隔立刻歸零，下次掉線會馬上重試。
- 每次重連都會寫進事件紀錄（`camera=… reconnecting`）。
- 退避的時間單位是**稽核次數**不是秒，所以改 `AUDIT_INTERVAL_MS` 會同時改變重連節奏。

實作在 `src/cctv_wall/ui/wall.py`；退避節奏由 `tests/test_reconnect.py` 守住。

## 設定視窗

左邊樹狀圖是「地點 → 攝影機」，右邊是欄位。改欄位時 **可播放網址預覽** 會即時顯示
組出來的網址（密碼遮成 `****`），組不出來就顯示錯誤原因（例如
`vendor 'custom' requires a path_template`）。

表單刻意分成兩層：**基本設定**只有「攝影機顯示名稱」與「影像來源網址或檔案路徑」，
多數來源（MP4、YouTube、已知的完整 RTSP 網址）填這兩欄就夠。需要用 IP、帳密、
vendor 樣板組網址時，才展開**進階連線設定**。

| 操作 | 行為 |
| --- | --- |
| 樹狀列表空白處按右鍵 | 新增地點（名稱重複時自動加序號，並立刻進入改名狀態） |
| 地點按右鍵 | 新增攝影機、複製、重新命名、**上移／下移**或刪除整個地點 |
| 攝影機按右鍵 | 複製、**上移／下移**或刪除該支攝影機 |
| `上移`／`下移` | 調整排列順序。地點順序＝側欄清單順序，攝影機順序＝影像牆格子順序；已在頭尾時該選項會變灰 |
| 地點／攝影機連點兩下 | 直接在樹狀清單內修改名稱 |
| 在來源網址欄貼上 RTSP 網址 | **自動拆出** host／port／帳號／密碼填進進階欄位並展開它；原網址保持不動，仍是實際播放用的來源 |
| `瀏覽…` | 選本機影片檔（mp4/mkv/avi/mov/ts/m3u8） |
| `IP +1` | 將目前表單中的 IPv4／IPv6 位址遞增一位，適合連號攝影機 |
| `儲存並重新載入` | 自動套用目前攝影機表單、寫入 `workspace.json` 並重載影像牆 |
| `取消` | 放棄所有未存檔的編輯 |

### 欄位

| 欄位 | 區塊 | 說明 |
| --- | --- | --- |
| 攝影機顯示名稱 | 基本 | 留空就用網址或 `host:port`，上限 48 字 |
| 影像來源網址或檔案路徑 | 基本 | 填了就直接用它，忽略所有 IP 欄位（MP4、YouTube、完整 RTSP 網址用這欄） |
| IP／主機名稱 | 進階 | 攝影機位址，例如 `10.0.0.5` |
| 連接埠 | 進階 | RTSP 埠，預設 `554`，範圍 1–65535 |
| 帳號／密碼 | 進階 | RTSP 帳密，會自動做 URL 編碼（`p@ss/1` → `p%40ss%2F1`） |
| 自訂路徑 | 進階 | `攝影機品牌 = custom` 時自己填樣板 |
| 攝影機品牌 | 進階 | RTSP 路徑樣板，見下節 |
| 串流 | 進階 | `1` = 主碼流（最高解析度），`2`/`3`/`4` = 子碼流 |
| 畫質 | 進階 | `auto` / `1080p` / `720p` / `480p` / `360p` |

## Vendor 路徑樣板

| Vendor | 樣板 | Stream=1 的結果 |
| --- | --- | --- |
| `generic` | `stream{stream}` | `rtsp://host:554/stream1` |
| `hikvision` | `Streaming/Channels/10{stream}` | `…/Streaming/Channels/101` |
| `dahua` | `cam/realmonitor?channel=1&subtype={stream0}` | `…?channel=1&subtype=0` |
| `reolink` | `h264Preview_01_{main_sub}` | `…/h264Preview_01_main` |
| `tapo` | `stream{stream}` | `rtsp://host:554/stream1` |
| `custom` | 自己填 | — |

樣板變數：

| 變數 | 意義 | Stream=2 時 |
| --- | --- | --- |
| `{stream}` | 使用者選的編號（1 起算） | `2` |
| `{stream0}` | 0 起算（Dahua 的 subtype） | `1` |
| `{main_sub}` | `main`（stream 1）或 `sub`（其他） | `sub` |

路徑因機型與韌體而異，對不上就用 `custom` 自己填。
要新增品牌只需在 `src/cctv_wall/vendors.py` 的 `VENDOR_TEMPLATES` 加一行，
URL 組裝與 GUI 都不用改。

## Quality 實際改了什麼

- **RTSP 攝影機**：解析度由攝影機端決定，換 **Stream** 才會換解析度
  （stream1 通常 1080p、stream2 約 720p、stream3 約 360p，依機型設定）。
  這裡不做即時轉檔，所以 **Quality 對 RTSP 沒有作用**。
- **HLS / DASH**（`.m3u8` 等）：加上 `:adaptive-maxheight=N`，真的會挑較低的 rendition。
- **YouTube**：轉成 yt-dlp 的 `best[height<=N][protocol^=http]/best[height<=N]/best`，
  取單一 muxed 串流，libvlc 不必自行配對音視訊。

RTSP 一律走 TCP（`:rtsp-tcp`）：多一點延遲，換來掉封包時不會整片馬賽克。

YouTube 解析優先用 PATH 上的 `yt-dlp` 執行檔；打包後 PATH 上沒有，會自動改用
內含的 `yt_dlp` Python 模組。

## 記憶功能

改任何設定或關閉視窗時，會立刻寫回 `workspace.json`：

| 記住的東西 | 欄位 |
| --- | --- |
| 所有地點與其攝影機（含帳密、vendor、stream、quality） | `sites` |
| 最後看的地點 | `last_site` |
| 效能檔 | `performance` |
| 視窗大小與位置 | `geometry` |
| 介面語言 | `language` |

存檔是**原子寫入**（先寫 `.tmp` 再 `os.replace`），中途斷電或磁碟滿不會留下半截的設定檔。
檔案位置：開發時在專案根目錄，打包後在 exe 旁邊，兩者都可用 `CCTV_WALL_CONFIG` 覆寫。

## workspace.json

從 [`workspace.example.json`](../workspace.example.json) 複製一份改名為 `workspace.json`，
或直接用設定視窗建立。

| 欄位 | 必填 | 預設 | 限制 |
| --- | --- | --- | --- |
| `sites[].name` | 是 | — | 不可空白、不可重複 |
| `url` | `host` 未填時必填 | `""` | 有值就優先使用 |
| `host` | `url` 未填時必填 | `""` | — |
| `port` | 否 | `554` | 1–65535（`0` 會被拒絕，空字串才是「用預設」） |
| `user` / `password` | 否 | `""` | 自動 URL 編碼 |
| `vendor` | 否 | `generic` | 須為上表之一 |
| `path_template` | `vendor=custom` 時必填 | `""` | — |
| `stream` | 否 | `1` | 1–4 |
| `quality` | 否 | `auto` | `auto`/`1080p`/`720p`/`480p`/`360p` |
| `performance` | 否 | `low_end` | 不認識的值會安全退回 `low_end` |
| `language` | 否 | `zh_TW` | `zh_TW`（繁體中文）或 `en`；可於主畫面切換 |

載入時逐筆驗證，出錯會明確指出位置，例如
`workspace.json: sites[0]: camera[1]: port must be 1-65535, got 0`，不會默默吃掉。

> **密碼是明碼存在這個檔案裡。** 不要進版控、不要放在共用磁碟。
> 見 [SECURITY.md](../SECURITY.md)。

# 使用說明

## 主畫面

| 操作 | 結果 |
| --- | --- |
| 左側地點列表 | 樹狀清單。點地點切換地點（**只有選中的地點會建立連線**）；展開後點單台攝影機會切到該地點並只放大那一格，側欄、頂部列與 AI 側欄保持可操作；再點同一台或按 `Esc` 還原格狀 |
| 左側按住 `Ctrl`（或 `Shift`）點攝影機 | 只看這幾台，可以跨地點，例如 1N1 的 .1 加 9N7 的 .4：選兩台以上時影像牆只顯示它們，頂部列顯示所有涉及的地點，這些地點的 AI 連線都會連上（側欄每筆前面標地點）；再按一次可移除；點地點列、按 `Esc`、一般點擊某台或換地點就回到原本的地點。不會存檔 |
| 側欄右緣拖曳 | 調整側欄寬度（160–800），寬度與是否隱藏都會記住 |
| 左側清單拖曳 | 拖地點改地點順序、拖攝影機改同地點內的順序，放開即存檔。不能把攝影機拖到別的地點，那要在設定視窗做 |
| 左側地點按右鍵 | 新增攝影機…、複製地點、重新命名、AI 辨識連線…、刪除地點 |
| 左側攝影機按右鍵 | 編輯攝影機…（只編輯這一台：名稱、RTSP 網址、帳號、密碼）、刪除攝影機 |
| 左下 `地點與攝影機` | 開啟設定視窗，管理所有地點與攝影機（含排序） |
| 左下 `AI 辨識連線` | 設定**目前地點**的 AI 辨識結果 TCP 連線 |
| 雙擊任一格影像 | 只放大該格（不開新視窗，側欄與頂部列保留）；再次雙擊或按 `Esc` 回到原本頁面 |
| 影像上按右鍵 | 快速切換該攝影機的 Stream 1～4；只有網址含串流標記（如 `/stream2`、`?stream=2`）時才有作用 |

在地點清單上可以用方向鍵：`↑`／`↓` 移到地點就切換地點、移到攝影機就放大那一台，移回地點列（或再點一次同一台）就還原格狀；`←`／`→` 收合／展開地點。

開啟程式時，視窗會依目前頁的格數自動調整大小，讓每格剛好是 16:9（一般攝影機的畫面比例）；之後手動縮放就不再干涉。放大縮小視窗時只有影像牆變寬變窄，側欄寬度不變。

影像不會無故中斷：切換單台攝影機的串流、或編輯畫面上的一台攝影機時，只有那一格重新連線（開啟嚴格同步時因為共用時鐘，才會整頁重新連線）。

快捷鍵：

| 按鍵 | 作用 |
| --- | --- |
| `Ctrl+B` | 顯示／隱藏左側地點清單 |
| `PgUp` / `PgDn` | 上一頁／下一頁 |
| `Ctrl+PgUp` / `Ctrl+PgDn` | 上一個／下一個地點 |
| `F5` | 重新連線目前可見的攝影機 |
| `F11` | 全螢幕 |
| `Esc` | 逐層退回：全螢幕 → 放大的單格 → 填滿程式畫面 |

頂部列（由左至右）：

| 項目 | 作用 |
| --- | --- |
| `☰` | 顯示／隱藏地點清單（同 `Ctrl+B`） |
| 地點名稱、`● 4/4 路播放中` | 目前地點與可見格的播放路數 |
| 播放器／CPU／記憶體 | 本程式的播放器數、CPU 用量與工作集記憶體，CPU 每 2 秒取樣一次 |
| `‹` 第 X / Y 頁 `›` | 同一地點內翻頁 |
| `▦ 4` 每頁格數 | 1–36，可直接輸入、滾動滑鼠滾輪或按方向鍵，**立即生效**並記住 |
| 語言下拉 | 繁體中文 ／ English，**立即套用**並記住 |
| `◐` 外觀 | 跟隨系統 ／ 深色 ／ 淺色，立即套用並記住（連 Windows 標題列一起變色），影像不中斷 |
| `⛶`（四角向外） | 以影像填滿程式畫面（收起導覽與工具列，視窗改為無邊框，可拖曳邊緣移動與縮放）；再按或 `Esc` 還原 |
| `同步` | 切換 GStreamer 嚴格時間戳同步，見 [TROUBLESHOOTING.md](TROUBLESHOOTING.md) |
| `AI` | 收合／展開 AI 辨識結果側欄；只在地點設有 `ai_feeds` 時出現 |
| 長條圖圖示 | 在每格影像左上角顯示攝影機狀態，每秒更新：解析度、每秒實際顯示幀數、丟幀數（累計）、位元率、重連次數。畫面卡頓時先看這裡：fps 明顯低於攝影機設定代表電腦或網路跟不上，丟幀持續增加代表解碼來不及。再按一次關閉；不會存檔。嚴格同步時無法顯示 |
| `↻` | 重新連線目前可見的攝影機（同 `F5`） |
| `☷` | 事件紀錄：直接在程式內看 `cctv-wall.log` 的尾端，可重新整理 |

CPU 是本程式佔整台電腦的百分比；滑鼠移上去可看播放器數與約用幾顆核心。
影像一律靜音，不解碼音訊（VLC 以 `--no-audio` 啟動）。

為降低低階電腦與 NVR 同時建立多條 RTSP 連線的壓力，當前頁的攝影機會依每頁格數錯開建立，
切換地點或頁面時則立即取消尚未建立的連線並釋放所有舊播放器。

畫面自動排成接近正方形的格子：4 路 → 2×2，5～6 路 → 2×3，9 路 → 3×3，16 路 → 4×4。

單格狀態刻意分成兩級，避免正常的緩衝把畫面塞滿文字：

| 情況 | 呈現 |
| --- | --- |
| 播放中 | 沒有任何覆蓋物，滑過去的提示顯示「播放中」 |
| 連線中／未收到影像 | 只更新該格的滑過提示，不遮擋畫面 |
| 連線失敗 | 該格顯示紅色訊息與原因，其他畫面照常播放 |

## 斷線自動重連

攝影機掉線後那一格會自己重連，不需要人工介入。

- 判斷來源是 `WallView.audit_now()` 每 5 秒一次的健康稽核。播放狀態落在
  `ERROR` / `ENDED` / `IDLE`，或一開始就連不上時，就排入重連。
- **正在連線中（`OPENING`）不算掉線**：低階電腦協商本來就慢，把它當故障
  會不斷打斷一個其實正在連線成功的來源。
- 退避間隔 5 → 10 → 20 → 30 秒（上限 30 秒），避免壞掉的來源被反覆猛打。
  影像一旦恢復，間隔立刻歸零，下次掉線會馬上重試。
- 每次重連都會寫進事件紀錄（`camera=… reconnecting`）。
- 退避的時間單位是**稽核次數**不是秒，所以改 `AUDIT_INTERVAL_MS` 會同時改變重連節奏。

實作在 `src/cctv_wall/ui/wall.py`；退避節奏由 `tests/test_reconnect.py` 守住。

## AI 辨識結果對照（TCP）

某些專案的 AI 端會用 TCP 回傳辨識結果。在地點加上 `ai_feeds`（可多條連線，每條可帶多台攝影機），
本程式會**主動連到**每個 AI 端，把結果顯示在兩個地方：

- **畫格下方一行**：該攝影機最新一筆結果，開頭是 AI 時間，可直接對照畫面上攝影機 OSD 的時間；
  左緣的色條與側欄中該攝影機的圓點同色。每收到一筆新結果，整條會以該顏色亮起約 1 秒再恢復，
  連續更新時一直亮著；刻意不用淡出動畫，遠端桌面觀看時也看得到。
- **右側「AI 辨識結果」側欄**：完整歷程，**由舊到新往下排**（保留 500 筆）。每筆第一行是攝影機
  （未命名時只顯示 IP）與時間、前面的彩色圓點對應畫格色條，第二行起是內容並依側欄寬度換行。
  停在最底時會自動跟著最新一筆；往上捲回去看時不會被拉走。可依攝影機篩選；點一筆就放大那台攝影機。
- **連線狀態**：側欄頂端每條連線一行，綠點＝已連線、黃點＝正在連線／重連中。工具列 `● AI` 按鈕的圓點
  全部連上時為綠色、有任一條未連上時為黃色，側欄收起時也看得到；按它可收合側欄。

### 在介面中設定

按左下角的「AI 辨識連線」（設定目前地點），或在左側欄任一**地點**上按右鍵 →「AI 辨識連線…」（設定視窗的地點右鍵選單也有同一項）：

1. 「新增連線」，填 **AI 端 IP / 主機** 與同一行的**連接埠**、**顯示延遲**、**對齊方式**（見下方〈時間對齊〉）。
2. 「攝影機對照」→「新增對照」：左欄填 AI 端送來的識別值（例如 `A001`），右欄從選單選本地點的攝影機（未命名的攝影機以網址顯示，也可以選）。
3. 「訊息格式（進階，JSON）」填 `camera_key`、`time_key`、`skip`、`skip_empty`、`labels`（欄位說明見下表）。
   第二條連線按「新增連線」時會**沿用目前所選連線的格式**，通常只需改 IP 與對照。
4. 「畫格下方顯示」（在攝影機對照右邊）：選**分類欄位**（選項是訊息格式 `labels` 裡的欄位，例如 `eventType`），
   再勾要留在畫格下方的種類。每勾一種就多一行、各留該種最新的結果，例如勾「路口停等偵測」＋「距離偵測」
   就有兩行；行的順序依 `labels` 裡的順序。沒勾的種類只出現在側欄。選「不分類」或都不勾時只留最新一筆。
   欄位在 `payload` 裡（例如 `vdType`）也可以。勾「按確定時套用至所有地點」會把這組設定複製到每個地點的每條連線。
   對照表的「只顯示」欄可以替**單台攝影機**篩選，例如 A001 只看 `vdType` 為汽車、卡車的結果：
   不符合的結果在畫格下方與側欄都不顯示，沒有該欄位的結果也不顯示；選「全部」取消篩選。
5. 按「確定」即存檔。從左側欄開啟的立刻生效；從設定視窗開啟的，在關閉設定視窗時生效。
   設定有誤（例如同一台攝影機被兩條連線對到）會在按確定時指出是第幾條連線、哪個欄位。

對應的 `workspace.json` 內容如下，也可以直接手動編輯（請先關閉程式，否則關閉時會被覆蓋）。

範例：一個地點、兩條連線，每條各帶兩台攝影機，且兩邊都用 `A001`/`A002` 稱呼自己的攝影機。
`labels` 把代碼換成文字，`skip_empty` 略過「目前沒有物件」的狀態回報：

```json
"ai_feeds": [
  { "host": "192.168.1.50", "port": 9000,
    "camera_key": "cameraName", "time_key": "created", "delay_ms": 1500,
    "cameras": { "A001": "Front Gate", "A002": "Lobby" },
    "skip_empty": ["payload"],
    "labels": {
      "eventType": { "0": "未知事件類型", "1": "距離偵測", "2": "淨空區狀態",
                     "3": "車流統計", "4": "路口停等偵測" },
      "vdType": { "1": "公車", "2": "汽車", "3": "機車", "4": "行人",
                  "5": "卡車", "6": "大卡車", "7": "腳踏車" } } },
  { "host": "192.168.1.51", "port": 9000,
    "camera_key": "cameraName", "time_key": "created", "delay_ms": 1500,
    "cameras": { "A001": "Dock", "A002": "Yard" },
    "skip_empty": ["payload"],
    "labels": { "…": "同上" } }
]
```

上例中 `{"eventType":1,"cameraName":"A001",...,"payload":[{"distance":50,...,"vdType":3}]}` 會顯示為
`eventType=距離偵測  payload=[{"distance":50,...,"vdType":"機車"}]`。

AI 端每行送一個 JSON 物件，例如：

```json
{"eventType":4,"cameraName":"A001","created":"2026-10-19 12:10:49.750","payload":[{"trackingId":667814,"vdType":2}]}
```

| 欄位 | 預設 | 說明 |
| --- | --- | --- |
| `host` / `port` | 必填 | AI 端位址，1–65535 |
| `camera_key` | `camera` | 訊息中標示攝影機的欄位 |
| `time_key` | `ts` | AI 事件時間欄位；可用 epoch 秒、epoch 毫秒或 ISO 8601（`2026-10-19 12:10:49.750` 也可），沒有時區視為本機時間；空字串表示不用 |
| `cameras` | 無 | AI 端識別值 → 攝影機顯示名稱。不設時識別值本身要等於顯示名稱；設了就只收表內的值 |
| `skip` | 無 | `欄位: [值, …]`，任一相符就略過，例如 `{"eventType": [3]}` 不看車流統計 |
| `skip_empty` | 無 | 欄位清單；任一欄位為空（`null`、`""`、`[]`、`{}`）就略過 |
| `labels` | 無 | `欄位: {代碼: 文字}`；訊息中**任何層級**的同名欄位都會換成文字，沒列到的代碼原樣顯示 |
| `delay_ms` | `1500` | 顯示延遲，見下方〈時間對齊〉，0–30000 |
| `align` | `received` | `ai_time`＝AI 時間＋延遲才顯示；`received`＝收到後延遲才顯示。舊設定沒有此欄位時為 `received`；介面新增的連線預設 `ai_time` |
| `tile_key` | 無 | 畫格下方依這個欄位分行（用換成文字之前的原始值比對；`payload` 裡的欄位也可以） |
| `tile_values` | 無 | 要留在畫格下方的值，例如 `["4", "1"]`，每個值一行；不設時只留最新一筆。需要 `tile_key` |
| `camera_filters` | 無 | `AI 端識別值: {欄位: [值, …]}`，例如 `{"A001": {"vdType": ["2", "5"]}}`：該攝影機只顯示欄位值相符的結果（任何層級、任一筆相符即可），沒有該欄位的結果不顯示。識別值必須在 `cameras` 表內 |

- **換專案、格式不同時**：只要仍是「每行一筆 JSON」，改上表設定即可（欄位名稱、攝影機識別、時間格式、
  略過規則、代碼文字），不用改程式。非 JSON 的格式（二進位封包、XML…）才需要改 `ai_feed.parse_line`，
  連線與顯示不受影響。
- 只有畫面上正在顯示的地點會連線（跨地點選取時是所有涉及的地點）；切換地點時，原地點的連線會斷開，
  加選另一地點的攝影機時，已連上的連線不會中斷。
- 有 `ai_feeds` 的地點，攝影機名稱不可重複；同一台攝影機也不能被兩條連線對到。
- 其餘欄位以 `欄位=值` 顯示，陣列／物件以精簡 JSON 呈現。不是 JSON、缺攝影機欄位、或不在 `cameras`
  表內的行會略過；同一種問題只在事件紀錄寫一次，避免洗掉日誌。
- **時間對齊**：影像有播放緩衝延遲，TCP 結果通常比畫面早到，所以每筆結果延後 `delay_ms` 才顯示。
  延後的起點由**對齊方式**決定（每條連線各自選）：
  - **依 AI 時間（建議）**：從訊息裡的 AI 時間（`time_key`，例如 `created`）起算。AI 端處理有時快有時慢，
    這個差異不會影響顯示時刻，只剩大致固定的影像延遲要校準。需要 AI 主機與本機都校時（NTP）；
    沒有時間欄位、或兩端相差超過 2 秒（側欄標 ⚠）的那一筆，自動改依收到時間。
  - **依收到時間**：從本機收到那一刻起算，AI 端處理時間的快慢會直接變成誤差，適合 AI 端沒有可靠時間時。
  校準方式：看畫格上攝影機 OSD 的時間，對照下方結果條開頭的 AI 時間；結果比畫面早出現就把延遲調大。
  每條連線各自設定，兩台 AI 端延遲不同時可分開校準。
- AI 時間與本機接收時間相差超過 2 秒時，側欄該筆會標 ⚠，滑過可看相差秒數，通常代表兩端沒有 NTP 校時。
- 每條連線各自斷線、各自以 1→2→4…30 秒退避自動重連，狀態逐條以綠／黃點顯示在側欄頂端。

## 設定視窗

左邊「地點列表」是「地點 → 攝影機」樹狀圖，右邊是攝影機欄位，右下角依序是 `新增`、`刪除`、`儲存`；關閉用視窗右上角的 ×。還沒有任何地點時，列表正中間有 `新增地點`；之後在列表空白處按右鍵新增。

新增／改名／移動／刪除地點或攝影機、AI 辨識連線都當下寫入 `workspace.json`。
**攝影機欄位的修改會先暫存**：改完切到別台不會遺失（清單中以斜體標示），按 `儲存` 時先列出
「哪台改了哪些欄位」（名稱顯示新舊值，網址與帳密只列欄位名），確認後一次寫入；有誤時在表單下方顯示原因，
全部都不存。帶著未儲存的修改關閉視窗，會詢問要儲存、捨棄或取消。
關閉設定視窗時，只有畫面上的地點真的被改動才重新連線；沒改或只改了別的地點，影像不會中斷。

| 操作 | 行為 |
| --- | --- |
| 樹狀列表空白處按右鍵 | 新增地點（名稱重複時自動加序號，並立刻進入改名狀態） |
| 地點按右鍵 | 新增攝影機、重新命名地點、AI 辨識連線…、**上移／下移**、刪除，以及新增地點 |
| 攝影機按右鍵 | **上移／下移**、刪除，以及新增地點 |
| `上移`／`下移` | 調整排列順序。地點順序＝側欄清單順序，攝影機順序＝影像牆格子順序；已在頭尾時該選項會變灰 |
| 地點／攝影機連點兩下 | 直接在樹狀清單內修改名稱 |
| 在攝影機欄位按 `Tab`／`↑`／`↓` | `Tab` 換到下一個欄位；`↑`／`↓` 換到上一台／下一台攝影機（跳過地點列），游標留在同一個欄位，改到一半的內容會暫存 |
| `新增` | 清空表單，填好後按 `儲存` 加到所選地點 |
| `刪除` | 刪除所選攝影機；選的是地點時會先確認 |
| `儲存` | 新增中的攝影機直接加入；其他暫存的攝影機修改確認後一次寫入（在欄位中按 Enter 也可） |

複製地點只在主畫面左側欄的地點右鍵選單。

### 欄位

| 欄位 | 說明 |
| --- | --- |
| 攝影機顯示名稱 | 留空就顯示網址（不含帳密），上限 48 字 |
| RTSP 網址 | 必填，例如 `rtsp://192.168.1.10:554/stream1`；也可填本機影片路徑。可直接貼上含帳密的網址（`rtsp://admin:密碼@192.168.1.10:554/stream1`），離開欄位或按 Enter 時帳密會移到帳號／密碼欄並取代原值 |
| 帳號／密碼 | RTSP 帳密，不存進網址，播放時才組進去並自動做 URL 編碼（`p@ss/1` → `p%40ss%2F1`） |

RTSP 一律走 TCP（`:rtsp-tcp`）：多一點延遲，換來掉封包時不會整片馬賽克。
想省頻寬與 CPU 就把網址指向子碼流（例如 `/stream2`），解析度由攝影機端決定。

### 舊設定自動轉換

舊版 `workspace.json` 以 `host`／`port`／`vendor`／`path_template`／`stream` 描述攝影機、
以 `performance` 效能檔決定每頁格數。載入時會自動轉換：攝影機依舊廠牌樣板
（`src/cctv_wall/vendors.py`，現在只用於這個轉換）組成網址，`quality` 直接忽略；
`performance` 換成每頁格數（`low_end` → 4、`balanced` → 9、`full` → 16）。
下一次存檔就寫成新格式。

## 記憶功能

改任何設定或關閉視窗時，會立刻寫回 `workspace.json`：

| 記住的東西 | 欄位 |
| --- | --- |
| 所有地點與其攝影機（名稱、網址、帳密）、AI 辨識連線 | `sites` |
| 最後看的地點 | `last_site` |
| 每頁格數 | `tiles_per_page` |
| 側欄寬度、是否顯示 | `sidebar_width`、`sidebar_visible` |
| 嚴格時間戳同步開關 | `strict_sync` |
| 視窗大小與位置 | `geometry` |
| 介面語言 | `language` |
| 外觀主題 | `theme` |

存檔是**原子寫入**（先寫 `.tmp` 再 `os.replace`），中途斷電或磁碟滿不會留下半截的設定檔。
檔案位置：開發時在專案根目錄，打包後在 exe 旁邊，兩者都可用 `CCTV_WALL_CONFIG` 覆寫。

## workspace.json

從 [`workspace.example.json`](../workspace.example.json) 複製一份改名為 `workspace.json`，
或直接用設定視窗建立。

| 欄位 | 必填 | 預設 | 限制 |
| --- | --- | --- | --- |
| `sites[].name` | 是 | — | 不可空白、不可重複 |
| `sites[].ai_feeds` | 否 | 無 | 連線清單，見〈AI 辨識結果對照〉 |
| `cameras[].name` | 否 | `""` | 上限 48 字；留空時顯示不含帳密的網址 |
| `cameras[].url` | 是 | — | RTSP 網址或本機影片路徑；網址內的帳密載入時會移到 `user`／`password` |
| `cameras[].user` / `password` | 否 | `""` | 播放時才組進網址並自動 URL 編碼；密碼存檔時以 DPAPI 加密 |
| `tiles_per_page` | 否 | `4` | 1–36；舊版的 `max_tiles` 會被忽略 |
| `sidebar_width` | 否 | `260` | 160–800 |
| `sidebar_visible` | 否 | `true` | — |
| `strict_sync` | 否 | `false` | 是否使用 GStreamer 嚴格時間戳同步；開啟後每格要等到關鍵影格與共同播放時間才出畫面，期間畫格下方顯示「同步中」 |
| `language` | 否 | `zh_TW` | `zh_TW`（繁體中文）或 `en`；可於主畫面切換 |
| `theme` | 否 | `system` | `system`（跟隨 Windows）、`dark` 或 `light`；可於頂部列 `◐` 切換 |

舊欄位（攝影機的 `host`／`port`／`vendor`／`path_template`／`stream`／`quality`，
以及 `performance`）仍可讀取，見〈舊設定自動轉換〉。

載入時逐筆驗證，出錯會明確指出位置，例如
`workspace.json: sites[0]: camera[1]: camera needs a url`，不會默默吃掉。

> **攝影機網址與帳號是明碼**；密碼存檔時以 Windows DPAPI 加密（無法解密時保留原密文，不會被清空）。
> 不要進版控、不要放在共用磁碟。
> 見 [SECURITY.md](../SECURITY.md)。
